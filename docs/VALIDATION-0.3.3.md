# Pame 0.3.3 validation

13 September 2026. Windows 11 / RX 9070 / wireless DualSense development PC.

## Background activity

The user requested individually selectable background controls, then required that launching games never show Windows elevation. App controls default on; the Windows-services switch defaults off and requires an explicitly selected installation add-on. Settings now includes a master switch and eleven choices. Copilot includes both the standalone Copilot package and Microsoft 365 Copilot. The Xbox choice targets the GamingApp package (app/tray), never Gaming Services or Xbox identity/device packages, and is skipped for Xbox games or another detected Xbox game. Widgets uses its package identity and its registered background activation arguments. OneDrive is asked to exit with `/shutdown` and restarted with `/background`; no unlink/reset/uninstall or forced sync-process termination is used. Games installed under known OneDrive roots are excluded. Browsers and other launchers have their original priority and power-throttling state saved, reduced and restored; they stay open. The active game's store and stores with another detected game remain at their original priority.

WSearch, DiagTrack and Spooler were actually stopped and restarted on this PC. MapsBroker and WMPNetworkSvc were already stopped and stayed stopped. The helper uses SCM status, stop/start controls and dependent-service checks, never edits startup type, and skips printing if its queue cannot be confirmed empty. It only accepts the fixed service allowlist. The service journal is administrator-owned under ProgramData, with Administrators/SYSTEM access. The final service add-on lives in administrator-owned Program Files, accepts only the configured user and installed Pame executable over a local pipe, rejects remote clients, and validates the service PID through SCM on the client. Requests are bounded and limited to begin/restore for five names. The service restores after disconnect, parent exit and service shutdown, with a durable journal and SCM restart recovery. Windows elevation is used only by the optional installer, never by game launch or Settings connection checks.

Testing of the earlier session-scoped prototype caught a named-pipe elevation/ownership mismatch and a Widgets restart failure. Explicit pipe ACLs plus peer validation resolved the former. The installed Widgets manifest showed that WidgetBoard runs as a registered background server; its fixed activation arguments resolved the latter. Failed recovery entries remain pending instead of being silently cleared.

## Limits

Closing and reopening an app does not restore arbitrary unsaved text or in-memory UI state. OneDrive client restart is not an assertion that every cloud operation or previous pause state has been reconstructed. Unknown package versions/process identities can be skipped, and explicit restore failures appear in the session report. The guardians cover owner-process death, not arbitrary total OS hangs. A system-wide hang or service recovery failure can leave a journal pending until the installed service restarts. The optional add-on currently authorizes one Windows user and one installed Pame path per computer. It has a separate Windows uninstall entry. Installation/update/removal of that add-on can require Windows administrator consent; ordinary Pame updates without selecting the add-on and all game launches do not. Pame does not stop security, networking, audio, Bluetooth/HID, anti-cheat, Gaming Services, SysMain, Windows Update or shared svchost processes. No FPS improvement claim is made.

The source/background scope is documented in `BACKGROUND-GAMING-RESEARCH.md`. This release implements the selected operations; the earlier research document's proposal-only statements describe its historical research stage.
