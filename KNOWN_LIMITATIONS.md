# Known limitations - 0.4.5 alpha

This release adds substantial UI and Windows functionality. It does not complete or certify every production-grade item in the supplied specification.

- **Updater:** automatic GitHub checks/downloads and next-start installation are available from 0.4.2. Older versions need the 0.4.2 installer once to gain the updater. Public alpha updates are enabled by default; stable-only mode is optional. Interrupted downloads restart from the beginning; installer failure does not offer a complete transactional rollback. Service-access add-on upgrades still require an explicit administrator installation. SHA-256 verifies integrity against GitHub, not a code-signing identity. See [updater details](docs/UPDATER.md).

- **Quick menu media:** Windows apps must publish System Media Transport Controls sessions. Pame browser observes ordinary HTML audio/video elements, including child frames; Web Audio-only, closed shadow-root and custom proprietary players may not expose controllable media. Previous/next is available when the website registers Media Session handlers; seeking depends on seekable content. Media rights, advertisements and provider restrictions remain controlled by the website/app. One playback source is selected at a time for commands; this is not a system audio mixer.
- **Background app windows:** restored app windows are hidden during a bounded 7.5-second recovery period, including secondary windows. The app's own behavior after recovery can still open a new window. Hiding keeps the process alive; it cannot preserve an app that chooses to exit itself. Apps already reopened before recovery are not hidden by this step.

- **Embedded browser:** uses Chromium through WebView2, not an independently maintained Chromium fork. Up to eight tabs, local profile and favorites are supported. Some DRM/subscription media and identity providers may restrict embedded browsers. No browser extensions, private mode, full download manager or automatic password manager UI is provided. Downloads require a Pame confirmation and go to Downloads/Pame; they are not opened automatically. Runtime installation requires Internet if WebView2 is absent. Full media-provider compatibility is not certified.
- **Controller notifications:** topmost, non-activating Windows overlays work above desktop/borderless windows. True exclusive fullscreen and Windows secure desktop can cover them. Battery warnings require a usable wireless battery report; some controllers report approximate levels. Synthetic multi-controller/battery transitions and actual native window focus are tested; the new hold/drag and notification behavior still needs an extended physical-controller trial.

- **Physical controllers:** a wireless DualSense connected during final validation and reported player 1, approximately 95% battery, rumble, RGB and player-light capabilities. On-device rumble/light appearance, extended physical navigation, Xbox/Switch, pairing repair and disconnect still need verification. SDL virtual-input tests pass.
- **Steam authentication:** this PC currently requires sign-in. Pame successfully opened the store for a game, but a full real-game launch/return test is pending. A native child-process fixture verifies session tracking and termination.
- **Store coverage:** Steam and Epic have manifest adapters. Several other stores rely on conservative registry/config evidence. Custom store locations, legacy/UWP Xbox games, encrypted launcher databases and unusual executables may need manual addition.
- **Uninstall:** Steam has a native uninstall/verify URI. Other stores are opened for their own management flow; Pame does not claim a unified in-shell uninstall for them. No actual game was uninstalled during tests.
- **Downloads:** Steam pending updates and manifest byte progress are real and refresh every five seconds on the Downloads page. Bandwidth, pause/resume, fresh incomplete installations and cross-store queues remain owned by stores. Cloud save state is unknown; automatic launcher shutdown is not enabled.
- **Overlay:** works as an independent topmost window. Exclusive fullscreen, anti-cheat focus rules, Game Bar and Steam's reservation of Guide can interfere. Start+Back and Ctrl+Alt+P are provided. Input is not blocked from the underlying game while the menu is open.
- **Telemetry:** CPU, RAM, GPU engine load, aggregate dedicated GPU memory, history and supported GPU temperature/clock/capacity are implemented. GPU engine values aggregate available adapters; the sensor card chooses the GPU with the most reported VRAM. RX 9070 temperature/clock/capacity were measured here. CPU temperature/clock remain unavailable on this PC without additional supported hardware access. Pame does not install that driver. PresentMon needs ETW access and compatible events; unavailable values are dashes.
- **Screenshots:** capture the primary Windows display through GDI. Some exclusive/protected game surfaces or HDR content may produce black or inaccurate captures. No game injection is used.
- **Bluetooth:** pairing may require a Windows-owned ceremony. Repair only unpairs the selected exact disconnected association endpoint and retries pairing; it does not sweep stale PnP records. Disconnect is not a universal hardware power-off guarantee.
- **Controller management:** no game input emulation, remapping, touchpad/gyro configuration, trigger effects or firmware management. Games may still need Steam Input or native controller support.
- **Profiles/optimization:** power, priority, CPU affinity, audio, refresh rate, GPU preference and controller color are available. Durable journals restore power/process/audio/display/GPU state on normal exit or the next Pame start. A crashed app cannot restore until restarted. Refresh rate applies to the primary display and only enumerated modes; only 60 Hz is exposed here, so mode validation was tested without changing modes. GPU selection is a Windows preference, not a guarantee, and store executables may need one successful launch before they are learned. HDR, fan controls, overclocking and automatic debloat are not implemented. Background activity has selected app/package closure, OneDrive exit/restart, browser/launcher priority reduction and a fixed service allowlist; see docs/VALIDATION-0.3.3.md. App reopening cannot restore arbitrary unsaved text or every in-memory state.
- **Startup/cleanup:** only current-user Run entries are managed; services, scheduled tasks and other users' entries are outside this UI. Optional package removal has individual/group selection and a review, covering 40 explicit package identities. It is scoped to the signed-in account, not all users or the provisioned Windows image. Reinstall links do not restore deleted app data. Actual package deletion was not used as a test.
- **Wi-Fi:** scanning and saved-network discovery were verified. New WPA2/WPA3 personal and open profiles are implemented, but actual network switching/new-password connection was not exercised. Enterprise, hidden-network creation and unsupported security flows remain in Windows. Scanning can depend on Windows location permission; Pame does not change it. Personal passwords are limited to the profile adapter's supported printable characters.
- **Desktop control:** automatically enabled for Windows/store handoffs; left/right click, hold/drag, scroll and Windows keyboard are supported. Native SendInput hold/release and browser clicks are tested. Elevated/protected windows may reject normal-user input. Pame does not bypass UAC or secure desktop. An extended physical-controller trial remains useful.
- **Windows handoffs:** store authentication, unsupported management operations, some pairing and security ceremonies remain owned by Windows/store UI. Pame itself provides controller navigation, including file browsing and text keyboards.
- **Rendering:** 0.3.2 removes the incorrect software-rendering override caused by an inactive virtual display adapter. Actual RX 9070 hardware composition at 3840 x 2160 and 150% DPI has been verified, with a typical composition interval around 17 ms in the navigation benchmark. Different TVs, HDR, refresh rates and monitor transitions still need broader testing. Low-resolution source artwork cannot gain detail through scaling.
- **Packaging:** unsigned, per-user x64 installer with in-app GitHub updates. Optional service access has its own administrator-installed add-on and uninstall entry. No gamepad-driven first-time installer or shell replacement. Signing, distribution hardening, accessibility/localization and longer hardware reliability tests remain before a production release.

Console mode hides the Explorer taskbar and desktop icon surfaces while fullscreen. Explorer stays running for file browsing and store protocols. A separate guardian restores the saved visibility, per-monitor wallpapers and wallpaper mode when Pame exits unexpectedly. Normal exit, recovery mode and Desktop control restore Windows too. Multi-monitor, slideshow and longer Spotlight rotation behavior need broader testing; the current single-monitor Spotlight state was restored in normal and forced-exit tests. `Ctrl+Alt+Shift+Escape`, `--safe-mode` and the **Pame Recovery** shortcut provide recovery. Startup is optional and repeated rapid startup attempts open recovery mode.

- **Standalone discovery and artwork (0.4.5):** scans use engine files, executable metadata and the LaunchBox Windows catalog. Obscure/renamed executables can require manual addition or edition selection. Archives, installers, ROMs, inaccessible folders, directory junctions and incomplete store downloads are excluded. Scans have a two-minute / 100,000-folder bound (30,000 for automatic scans); partial results are labelled. The first catalog download is about 103 MiB; its Windows index is cached locally. No account or API key is used. Some games have no separate logo or only low-resolution art. Source availability and complete catalog coverage are not guaranteed. See [discovery details](docs/GAME-DISCOVERY.md).
